# ES Footprint gateway design — Codex round 1 (2026-09-07)

Reviewed: revision 1. Verdict: REQUEST_CHANGES (7 findings, dispositioned in revision 2's change log).

1. **HIGH — doc:45–48** — Bar and outcome views roll sessions independently, but the hello exposes only one `footprint.sessionDate`. The design never defines which view owns that value or how a snapshot remains consistent if bootstrap records from the two Kafka topics arrive in different orders. A client can consequently pin one route using the other view’s session. **Required change:** define a shared, monotonic ISO-session coordinator for both views, or expose separate `barsSessionDate` and `outcomesSessionDate`; specify atomic hello snapshots and cross-topic rollover behavior, with out-of-order bootstrap tests.

2. **HIGH — doc:49** — G-R8 is neither numerically correct nor a real memory bound. `9,122 × 64 KiB` is about **570 MiB**, not 160 MB; accepting records up to 262,144 bytes permits roughly **2.23 GiB of raw bar bytes** before Java `String`, map-key, JSON, and object overhead. Outcomes have no oversize rejection at all, and the cited reference-session counts are observations rather than normative cardinality limits. No heap setting is visible in this worktree, so compatibility cannot be established. **Required change:** provide conservative retained-heap arithmetic against a specified deployment heap and introduce enforceable per-view byte/cardinality budgets—including outcomes—with deterministic eviction/rejection and metrics. Make deployment contingent on a verified heap margin.

3. **MEDIUM — doc:45–46** — Session rollover accepts any nonempty string lexicographically. A malformed but parseable record such as `sessionDate:"z"` can clear a valid ISO-date view and make all later valid sessions appear stale; a missing session date can also be inserted into the current view. This conflicts with the claimed monotonic ISO-date behavior and “foreign shape” safety. **Required change:** require a present, strictly valid canonical `YYYY-MM-DD` date—preferably parsed as `LocalDate`—before either view mutation; classify invalid/missing dates as shape drops and test invalid dates, missing dates, older dates, and year/month boundaries.

4. **MEDIUM — doc:48,63–64** — Outcome cursor totality is asserted but not fully specified. A `TreeMap<String,…>` key containing an unpadded decimal timestamp is lexicographic rather than numeric over the upstream epoch-ms domain, while behavior for malformed, wrong-timeframe, or nonexistent opaque cursors is undefined. G-R11 does not explicitly require collision/tie and invalid-cursor cases. **Required change:** define a tuple comparator `(timeframe, resolvedAtBarStartMs numeric, identity)` or a fixed-width encoding; define cursor validation/error behavior and test multiple identities at one resolution time, timestamp digit-length boundaries, delimiter-bearing identities, stale/wrong-timeframe cursors, and URL/JSON round trips.

5. **MEDIUM — doc:52** — The brokerless acceptance suite does not cover every normative requirement. Missing pins include topic/default settings, complete flag-off behavior (subscriptions, lazy views, hello bytes, HTTP 404 body/status, metrics), verbatim delivery and view-before-broadcast ordering, optional absent-topic startup, complete metric labels/counting, malformed-record containment, and the configured memory bounds. Allowlist membership alone also does not prove delivery behavior. **Required change:** expand G-R11 into explicit brokerless tests for every G-R1–G-R10 clause, including per-session routing tests proving all four events reach every authenticated socket and non-allowlisted events remain dropped.

6. **MEDIUM — doc:44,52; `FeedGatewayService.java:10361–10371,11517–11548`** — Allowlisting makes each footprint event a global fan-out in per-session authentication mode, bypassing `SessionRoutingEngine` and every session selection. The design mandates this but does not record the authorization/data-isolation consequence or prove that footprint payloads are safe for every authenticated user. **Required change:** explicitly classify footprint data as tenant/session-global and document the authorization decision; otherwise define a routable identity and selection rule. Test actual multi-session fan-out/isolation, not merely set membership.

7. **LOW — doc:31–34** — The upstream-record summary incorrectly says every record carries singular `timeframe`. The live grammars carry a `timeframes` object and no singular `timeframe` (`ES-FOOTPRINT-DESIGN.md:571–584`). **Required change:** say that bar and outcome records carry `timeframe`, while live records carry the fixed-key `timeframes` object.

The remaining AS-IS anchors and line numbers match the cited source. The external ES CVD page also ignores additional hello fields: `onHello` stores the object and reads only known `sessionDate`/`hwm` properties (`es-cvd.js:278–304`), so adding `footprint` is compatible.

VERDICT: REQUEST_CHANGES
