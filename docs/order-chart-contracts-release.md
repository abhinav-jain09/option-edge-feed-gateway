Web is pinned to retained contracts release 0.85.0 from Jenkins `options-edge-contracts/127`, source `89effc72f3c010aa1948f6384f15371696f60c11`, JAR SHA-256 `7dde369c83db34e1a613019229c79db9d7bb3f507e23ae41119b139e52c70403`. The gateway previously compiled the same source/version anew. ZIP timestamps can change its bytes, so this did not prove identical projection artifacts across consumers.

The existing gateway Install Contracts stage still clones the permitted contracts source and runs its unchanged Maven install/tests. It then validates the same immutable release lock as web against a successful, retained Jenkins release and its repository/source identity; verifies the bounded JAR and embedded POM bytes; and installs those exact bytes into its existing private workspace Maven repository. The normal recorded JAR SHA, ES4 transferred cache checks, packaged-JAR verification and image checks consequently bind to that qualified release. The permitted contracts SHA must match the lock before the CLI downloads or verifies anything. A different source/version/release requires an explicit reviewed lock change.

The helper is derived from the existing web qualification helper. Its gateway changes resolve the single permitted Maven version property, use the gateway's existing `.m2/repository` path, label its provenance as gateway, and bind the existing `CONTRACTS_PERMITTED_SHA` parameter. It uses the existing Install Contracts stage and adds no service or deployment stage. It archives the qualification receipt. No Linux test, mutation campaign, source guard, timeout or runtime deployment is bypassed.
