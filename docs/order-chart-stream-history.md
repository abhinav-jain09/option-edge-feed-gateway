# Order chart bootstrap history over the gateway socket

This PR implements the auction/footprint bootstrap portion of OP-P4-02, coordinated with [reconciliation PR1546](https://github.com/abhinav-jain09/options-edge/pull/1546) and [web client PR1553](https://github.com/abhinav-jain09/options-edge/pull/1553). OP-P4-01 and the remaining OP-P4-02 delta-flow, path, VWAP, signal and durable replay ownership remain incomplete. No new Kafka reader, REST endpoint, service or Jenkins job/stage is introduced. The OP-P4-02 proxy requirements for If-None-Match, compression and avoiding whole-body buffering are not delivered by this increment and remain open.

Registered authenticated sockets receive order-chart-history-hello with schemaVersion 1, available resources and maximum 16 records. Auction is advertised only when enabled and the shared backfill permit pool exists. Capabilities are not hydration readiness. Clients may request after capability and receive loading until the server's corresponding replay barrier completes. Disabled features or a footprint topic bound to a different event/source return unavailable. A detected incompatible binding revokes the footprint capability and requires corrected process configuration.

Request and response type are order-chart-history. Requests may include an integral limit from 1 through 16 (default 16). Requests use schemaVersion 1, a textual opaque requestId of 1–64 characters, resource and canonical sessionDate. Auction after is an inclusive minute cursor, empty initially. Footprint timeframe is 1m/5m/15m; after is an exclusive integral epoch-millisecond cursor and toMs an inclusive bound inside that futures session. The shared dispatcher enforces 1024 UTF-8 bytes using OrderChartHistory.MAX_REQUEST_BYTES; unregistered sockets are rejected before parsing.

Normal replies echo requestId/resource/sessionDate and include records/nextCursor/done. Footprint replies also echo validated timeframe and toMs. Error replies echo validated bounded identity fields only, contain an error, and never advance a cursor or report completion. A requested auction session absent from both held trade dates returns session_unavailable rather than a successful empty page. Current held sessions can legitimately contain no rows.

Each page reads at most 16 source records. The serialized response budget is min(512 KiB, wsMaxQueuedBytes()/4); the per-record byte budget is also enforced. Oversized pages halve their count until a page fits; a single oversized record returns record_budget with no cursor advance. Parsing and response serialization are byte-checked. Four fair backfill permits and the existing bounded asynchronous writer provide admission and delivery limits. Each adaptive auction source read increments the existing backfill-read counter; it is not a count of socket RPCs.

Footprint replay uses the actual DATABENTO/es-footprint-bar binding. The cache consumer closes OrderChartReplayGate before the cache-window seek, captures each partition's end offset and opens only after applied positions reach every barrier. Late adoption retains previous barriers. Same-attempt selected-source recovery does not discard ownership; only an owning cache-attempt failure invalidates it. New attempts replace ownership. Missing offsets, unassigned partitions and failed seeks remain loading. Position lookups occur outside the gate monitor; publication checks owner and revision, preventing an old lookup from reopening a newer replay. The monitor covers only an immutable bounded view-page capture; JSON parsing, shrinking and serialization run outside it. Completed gates avoid repeated position lookups until reopened.

Auction source reads, JSON parsing, adaptive shrink retries and serialization run under the existing incarnation/handoff lock, bounded by the page budget. Socket writes happen after releasing the lock. Bootstrap is not a frozen multi-page snapshot or durable replay. The client must preserve its existing live-correction barrier across pages, reject old request generations and retain admitted data across viewport changes. Older gateways omit the capability and keep the existing REST bootstrap fallback; stream-only completion is not claimed.
