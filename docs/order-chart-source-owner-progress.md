# Order chart stream source owner — unfinished

This branch continues the approved four-resource stream plan. It is not enabled, advertised, deployed or a replacement for the four existing HTTP readers. The source consumers, shared projection lifecycle, scope publication, serialization cache, replay pumps, client activation and load qualification still need implementation. No completion of OP-P4-01 is claimed.

The first source-owner components are an immutable subscription identity and the remaining memory-category admission owner. Requests require the exact effective environment, SPX, a canonical ISO date, 1m/5m/15m, and exactly delta-flow/path/vwap/signals. Resource ordering does not change scope identity. A resume cursor additionally binds its scope hash, epoch and JavaScript-safe revision. Duplicate JSON keys, trailing JSON, arbitrary fields, type coercions and oversized UTF-8 input are refused. Parsing deliberately has no unconditional RTH calendar gate: each resource must retain its own shared calendar/CASH/GLOBEX policy later.

The memory owner reserves source/projection32MiB, serialized snapshots8MiB and pending preparation/publication8MiB separately; journal8MiB and outbound8MiB retain their existing independent owners. Reservations must precede allocations. Resize refuses growth without available capacity and leaves the prior charge intact. Closing the coordinator prohibits new/growing work but does not erase allocations still held by actual owners. Releases are idempotent and notify outside the accounting lock. Reservation objects are independently capped128. These are ownership-byte accounting ceilings, not a demonstrated process physical-heap bound; consumers have not been attached to this owner yet.

Local reactor tests: four subscription tests and four budget tests passed, including parallel overcommit and close/in-flight accounting. The initial direct Maven run never reached tests because private contracts0.85.0 were absent from public repositories. One initial test compile failed because a var compound declaration was invalid; corrected before the passing reactor run. This is local source preparation, not the required ES4 Linux release qualification. The earlier primary gateway854 qualified existing main source and exact shared contracts release; it does not qualify this new branch.

No Kafka, Kubernetes or production change was made by these tests. Remaining integration must run both requested line-by-line reviews before PR/merge and exact-SHA Jenkins deployment.
