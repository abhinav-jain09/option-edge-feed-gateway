# Order chart delivery ownership (in progress)

These are prerequisites for OP-P4-01 in the reviewed Order chart stream design. They are wired into OutboundChannel with nonclosing chart admission and a namespaced vol-premium idle owner. The gateway subscription is not implemented; no runtime chart-stream feature is enabled by this change. Neither Phase4 nor the six-phase programme is complete.

OutboundIdleDispatcher bounds registration to four independent owners, schedules coalesced owner wakes outside channel/domain locks, rotates ready owners, and yields after32callbacks or2ms between callbacks. Replacement has a distinct handle so an old unsubscribe/fault cannot clear its successor. Callback failure removes only that owner and invokes its failure cleanup. Rejected handoffs remain ready for watchdog retry. Work identity fences an executor that publishes then throws. Production requires a bounded asynchronous executor; an injected inline test executor runs only one bounded slice, then relies on explicit watchdog retry to avoid recursive stack growth. Closing prevents new claims; a callback already claimed can finish, so its owner must still recheck socket/session authority per frame.

ChartOutboundBudget accounts at most8MiB chart wire copies globally,128KiB/two frames per owner,1024retained owners. Detaching an owner cannot forgive queued/in-flight leases; it occupies its owner slot until all copies are actually released. A lease releases once across racing write/discard paths, and the capacity wake runs outside the budget lock. The callback must schedule deduplicated bounded publication, never run socket I/O or domain work inline. These counters account wire copies, not raw source/projection/journal memory; the other approved categories remain to be implemented.

The fifteen focused tests cover owner replacement/isolation, fairness/yield, close, rejection, published-then-thrown tasks, inline test safety, concurrent wakes, global/per-owner admission, detach/close with live copies, racing release and reentrant/failing wakeup. Initial focused run passes. Final gateway integration must additionally prove accounting through actual channel send/discard and in-flight failure, nonclosing binary admission, concurrent vol-premium/chart publication, global fairness, subscriptions, authentication, bounded replay, cancellation and runtime load. Source reviews and existing Jenkins deployment remain outstanding for this gateway branch.

Channel integration adds a dedicated bounded publication executor (two workers,256queued tasks), watchdog retry and independent vol-premium/chart idle registrations. Chart copies reserve before cloning, retain their lease through an active blocking send, and release exactly once after send/discard. Queue headroom reserves control-message capacity; saturation parks rather than closes. Ten channel tests cover concurrency, actual send failures, authorization refusal, detach accounting and coexistence.
