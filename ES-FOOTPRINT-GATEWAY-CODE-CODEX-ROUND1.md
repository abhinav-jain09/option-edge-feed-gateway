# ES Footprint gateway relay — CODE gate, Codex round 1 (2026-09-07)

Reviewed commit: c5bdbdc. Verdict: REQUEST_CHANGES (5 findings, all remediated in the next commit).

1. **HIGH — [FeedGatewayService.java](/private/tmp/oe-gw-footprint/src/main/java/app/feedgateway/FeedGatewayService.java:2838), [FeedGatewayService.java](/private/tmp/oe-gw-footprint/src/main/java/app/feedgateway/FeedGatewayService.java:6283) — live-consumer retries replay and broadcast the keyed footprint cache window.** On every retry, `runLiveConsumerOnce` calls `seekToCacheWindow`; `cachePolicyFor` gives bars/outcomes a 24-hour window. Consequently the live consumer re-admits and broadcasts historical compacted bars/outcomes instead of seeking END. This contradicts G-R8a’s live-consumer semantics and can generate a large duplicate backfill over WebSockets. **Remediation:** make footprint partitions seek END in the live retry path, while preserving the full-session seek only for the cache consumer; add a behavioral retry/seek test.

2. **MEDIUM — [FootprintViews.java](/private/tmp/oe-gw-footprint/src/main/java/app/feedgateway/FootprintViews.java:225) — the bars cursor is not exclusive at epoch boundaries.** `afterMsExclusive + 1` overflows for `Long.MAX_VALUE`, and clamping `from` to `EPOCH_MAX_MS` makes `afterMs == EPOCH_MAX_MS` include the epoch-max record again. Both violate G-R7’s exclusive cursor contract. **Remediation:** return an empty page when `afterMs >= EPOCH_MAX_MS`, and avoid arithmetic before validating the range; test `EPOCH_MAX_MS` and `Long.MAX_VALUE`.

3. **MEDIUM — [FeedGatewayService.java](/private/tmp/oe-gw-footprint/src/main/java/app/feedgateway/FeedGatewayService.java:909) — startup refusal is not atomic.** `running` is set and the executor is created before the JVM-layout and topic-config checks. If either check refuses startup, `start()` exits exceptionally with `running=true` and an undisposed executor. **Remediation:** perform all footprint preflight validation before changing lifecycle state or allocating executors, or roll both back in a failure path.

4. **MEDIUM — [FootprintWiringTest.java](/private/tmp/oe-gw-footprint/src/test/java/app/feedgateway/FootprintWiringTest.java:54) — G-R11’s required predicate-seam test is replaced by source-text inspection.** The suite does not execute `PartitionRefresh.apply()` with a rejecting-then-accepting gate and therefore does not verify `Refresh.added()`, merged assignment, seek/caught-up effects, or both consumer flows. Other expressly enumerated behavioral pins are also absent, including malformed Spring parameter binding, real authenticated-socket fan-out through a fake sink, concurrent hello atomicity, and live retry seek behavior. The passing 1,062-test run therefore does not satisfy G-R11’s military-completeness bar. **Remediation:** introduce executable seams/fakes and add the enumerated behavioral tests instead of relying on string-position assertions.

5. **LOW — [GatewayController.java](/private/tmp/oe-gw-footprint/src/main/java/app/feedgateway/GatewayController.java:146) — the “ONE fixed 64 KiB buffer” and transient-memory claim is stronger than the implementation proves.** `BufferedOutputStream` adds 64 KiB on top of the servlet container’s own response buffer, while each record also creates a full `byte[]`. The one-record allocation is intended, but the claim that no additional response buffer exists is false and the `<0.32 MiB` proof omits the container buffer. **Remediation:** include the bounded servlet buffer in the memory proof/configuration, or write through a response stream whose buffering contract is explicitly controlled.
